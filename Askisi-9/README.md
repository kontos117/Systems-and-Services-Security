## Μέρος 1: Exploiting Greeter

### 1. Ανάλυση Ευπάθειας
Το πρόγραμμα `Greeter` παρουσιάζει ευπάθεια **Stack Buffer Overflow** στη συνάρτηση `readString`. Η αιτία είναι η χρήση της συνάρτησης `gets()`, η οποία διαβάζει δεδομένα από την είσοδο και τα αποθηκεύει σε έναν τοπικό buffer (`buf`) μεγέθους 32 bytes στο Stack, χωρίς να ελέγχει το μήκος των δεδομένων.

Αυτό επιτρέπει σε έναν κακόβουλο χρήστη να εισάγει περισσότερα από 32 bytes, υπερκαλύπτοντας γειτονικές περιοχές μνήμης, όπως τοπικές μεταβλητές (`Grade`) και τη διεύθυνση επιστροφής (Saved EIP).

### 2. Ανάλυση Μνήμης (GDB)
Με τη χρήση του GDB, αναλύσαμε τη δομή του Stack frame της `readString` και εντοπίσαμε τα εξής:
* **Διεύθυνση του `buf`:** `0xffffbdc8`
* **Διεύθυνση του Saved EIP (Return Address):** `0xffffbdfc`
* **Συνολικό Offset για το Return Address:** `0xffffbdfc - 0xffffbdc8 = 52 bytes`.
* **Θέση μεταβλητής `Grade`:** Βρίσκεται ακριβώς μετά τον buffer, δηλαδή στο **offset 32**.

### 3. Απαντήσεις στα Ζητούμενα

#### 3.1 Αλλαγή Βαθμού και ο Περιορισμός του '10'
Στόχος ήταν να λάβουμε βαθμό μεγαλύτερο του 6. Καταφέραμε να θέσουμε τον βαθμό ακριβώς στο **11**.

* **Πώς επιτεύχθηκε το 11:**
  Γνωρίζοντας ότι η μεταβλητή `Grade` ξεκινάει στο offset 32, κατασκευάσαμε το payload ώστε στα bytes 32-35 να γράφει την τιμή `0x0000000B` (Little Endian).
  * *Hex Payload:* `... \x0b\x00\x00\x00 ...`
  Το 11 αντιστοιχεί στον χαρακτήρα ASCII "Vertical Tab", ο οποίος δεν επηρεάζει τη λειτουργία της `gets()`.

* **Γιατί δεν μπορούμε να πάρουμε βαθμό '10':**
  Η τιμή 10 σε δεκαεξαδικό είναι `0x0A`, που αντιστοιχεί στον χαρακτήρα **Line Feed (`\n`)**. Η συνάρτηση `gets()` χρησιμοποιεί το `\n` ως χαρακτήρα τερματισμού της εισόδου. Επομένως, αν προσπαθήσουμε να εισάγουμε το `0x0A` στο payload, η `gets()` θα σταματήσει την ανάγνωση εκείνη τη στιγμή και θα αντικαταστήσει το `0x0A` με null byte (`\0`), καθιστώντας αδύνατη την εγγραφή της τιμής 10 στη μνήμη της μεταβλητής.

#### 3.2 Εκτέλεση Κελύφους (Arbitrary Code Execution)
Για την εκτέλεση κώδικα, εκμεταλλευτήκαμε το γεγονός ότι το πρόγραμμα αντιγράφει τα περιεχόμενα του `buf` στην καθολική μεταβλητή `Name`, η οποία έχει ρητά οριστεί ως εκτελέσιμη (`PROT_EXEC` μέσω `mprotect`).

**Μεθοδολογία Exploit:**
1.  **Shellcode Injection:** Χρησιμοποιήσαμε κώδικα μηχανής (shellcode 25 bytes) που εκτελεί την κλήση συστήματος `execve("/bin/sh")`.
    * *Σημείωση:* Χρειάστηκε να προσθέσουμε εντολή μηδενισμού του καταχωρητή `EDX` (`xor edx, edx`) στο shellcode για να διασφαλίσουμε ότι το όρισμα `envp` είναι NULL, αποφεύγοντας έτσι errors κατά την εκτέλεση.
2.  **Padding:** Γεμίσαμε τον υπόλοιπο χώρο μέχρι το offset 52 με τυχαίους χαρακτήρες, προσέχοντας να γράψουμε το `11` στη σωστή θέση του `Grade`.
3.  **Return Address Overwrite:** Αντικαταστήσαμε τη διεύθυνση επιστροφής (στο offset 52) με τη διεύθυνση της μεταβλητής `Name` (`0x080ef320`), όπως βρέθηκε στο GDB.

**Αποτέλεσμα:**
Κατά την επιστροφή της `readString`, ο έλεγχος πέρασε στο `Name` και εκτελέστηκε ο shellcode, δίνοντας πρόσβαση σε κέλυφος εντολών (`/bin/sh`).

#### 3.3 Η Τεχνική Διατήρησης του Κελύφους

Για την επιτυχή αλληλεπίδραση με το κέλυφος που ανοίγει το exploit, χρησιμοποιήσαμε την εντολή: `(cat payload; cat) | ./Greeter`

- Το `cat payload` στέλνει τα bytes του exploit για να γίνει το overflow.
- Το `;` διαχωρίζει τις εντολές.
- Το δεύτερο `cat` (χωρίς ορίσματα) αναλαμβάνει αμέσως μετά. Διαβάζει από το πληκτρολόγιο (stdin) και στέλνει τα δεδομένα στην έξοδο (stdout), η οποία μέσω του pipe (`|`) καταλήγει στο spawned shell.

Έτσι, το κανάλι επικοινωνίας παραμένει ανοιχτό, επιτρέποντας την εκτέλεση εντολών όπως `ls` και `whoami` στο νέο shell.

## Μέρος 2: Bypassing Data Execution Prevention (DEP)

Στο δεύτερο μέρος της εργασίας, κληθήκαμε να εκμεταλλευτούμε το πρόγραμμα `SecGreeter`. Σε αυτή την έκδοση, έχει ενεργοποιηθεί ο μηχανισμός DEP (NX bit), γεγονός που καθιστά το Stack μη εκτελέσιμο και εμποδίζει την εκτέλεση injected shellcode.

### 1. Μεταγλώττιση και Προετοιμασία
Αρχικά, ήταν απαραίτητο να απενεργοποιήσουμε το ASLR και να μεταγλωττίσουμε ξανά το πρόγραμμα χρησιμοποιώντας το παρεχόμενο `Makefile` (`make secure_greeter`), διαφορετικά δε μπορούμε να υπολογίσουμε σωστό offset.

### 2. Υπολογισμός Offset και Return-to-Libc
Για να παρακάμψουμε το DEP, χρησιμοποιήσαμε την τεχνική **Return-to-Libc**.
Χρησιμοποιώντας το GDB και ένα cyclic pattern, προκαλέσαμε crash στο πρόγραμμα. Ελέγχοντας τον `EIP` κατά το crash, υπολογίσαμε ότι η απόσταση μέχρι τη διεύθυνση επιστροφής είναι **44 bytes**.

### 3. Δημιουργία του Exploit
Στο script `generator_sec.py`, κατασκευάσαμε το payload ως εξής:
* **Padding:** 44 bytes 'A' για να φτάσουμε στο Return Address.
* **System Address:** Αντικαταστήσαμε το Return Address με τη διεύθυνση της `system()`.
* **Return from System:** Ως διεύθυνση επιστροφής της `system`, τοποθετήσαμε τη διεύθυνση της `exit()`, ώστε το πρόγραμμα να τερματίσει ομαλά.
* **Argument:** Τοποθετήσαμε τη διεύθυνση του string `"/bin/sh"` ως όρισμα για την `system()`.

## Μέρος 3: Bypassing ASLR

Στο τελευταίο μέρος, το πρόγραμμα `SecGreeterASLR` είναι 64-bit και έχουμε ενεργοποιημένο το ASLR, αλλάζοντας τις διευθύνσεις της libc σε κάθε εκτέλεση. Επίσης, χρειάστηκε να γίνει recompile (`make secure_greeter_aslr`) για να παραχθεί το σωστό εκτελέσιμο.

### 1. Εντοπισμός Διαρροής (Info Leak)
Δημιουργήσαμε το script **`fuzz_leak.py`**, το οποίο στέλνει πολλαπλά Format String specifiers (`%p`) στην πρώτη είσοδο του προγράμματος.
* Τρέξαμε το πρόγραμμα με GDB και χρησιμοποιήσαμε την εντολή `info proc mapping` για να βρούμε το εύρος διευθύνσεων (Start - End Address) όπου φορτώνεται η libc.
* Παρατηρήσαμε ότι η τιμή που επέστρεφε το **`%3$p`** (το 3ο στοιχείο στο Stack) ήταν πάντα μια διεύθυνση που ανήκε μέσα σε αυτό το εύρος της libc.

### 2. Υπολογισμός Offset
Γνωρίζοντας τη διεύθυνση που διαρρέει (Leak) και την πραγματική βάση της libc (Base) από το `info proc mapping`, υπολογίσαμε το σταθερό Offset:
> **Offset = Leak Address - Libc Base Address**

Αυτό το Offset μας επιτρέπει να υπολογίζουμε δυναμικά τη διεύθυνση βάσης της libc σε κάθε εκτέλεση του exploit (`Current Base = Leaked Address - Offset`).

### 3. Ανάλυση του Exploit
Το script `generator_aslr.py` αξιοποιεί τη βιβλιοθήκη pwn tools της python και λειτουργεί σε δύο στάδια:
1. Στέλνει `%3$p`, διαβάζει τη διεύθυνση που διαρρέει και υπολογίζει τη βάση της libc.
2. Κατασκευάζει ένα ROP chain για την αρχιτεκτονική x64.
    * Φορτώνει τη διεύθυνση του `"/bin/sh"` στον καταχωρητή `RDI`.
    * Καλεί την `system()`.
    * Προσθέσαμε επίσης ένα `ret` gadget για ευθυγράμμιση του Stack (16-byte alignment), αποφεύγοντας έτσι crashes που σχετίζονται με την εντολή `movaps` στο Ubuntu.
